## 2024-08-15 - Improved Form Accessibility on Auth Page
**Learning:** In purely vanilla JS applications like this, form validation often relies on dynamically toggling `display: none` on specific error message elements (e.g., `<p id="login-error">`). While visually effective, these changes are completely invisible to screen readers unless specifically marked up. Furthermore, standard `<label>` elements without explicit `for` attributes fail to programmatically associate with their input fields, making navigation confusing for assistive technologies.
**Action:** Always ensure that dynamically toggled error messages include `aria-live="polite"` (or `assertive`) so their appearance is announced by screen readers. Similarly, ensure every `<label>` has a `for` attribute matching the exact `id` of its corresponding `<input>` or `<select>` element to provide a robust, accessible form experience.
