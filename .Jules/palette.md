## 2024-05-15 - Missing form associations and silent error regions
**Learning:** Found a widespread pattern in this vanilla JS app where `<label>` elements consistently lacked `for` attributes, causing screen readers to fall back to heuristics instead of explicitly connecting the label to its corresponding form input. Furthermore, client-side form validation relied on dynamically removing `display: none` from inline error paragraphs, but lacked `aria-live` attributes, meaning screen reader users wouldn't be notified when validation failed.
**Action:** Always verify that `<label>` elements explicitly define `for` attributes pointing to their input IDs. When building vanilla JS form validation that toggles error visibility, proactively add `aria-live="polite"` to the container so state changes are appropriately announced.
