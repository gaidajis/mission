
## 2026-06-06 - Form Validations and Screen Readers
**Learning:** In this vanilla JS application, form validation error messages (like invalid login or existing email) are dynamically toggled using `display: none`. This means that when the element is shown, screen readers will not announce the error text unless `aria-live` is explicitly set, leaving visually impaired users unaware of the failure reason. Additionally, none of the form labels were natively associated with their corresponding inputs via the `for` attribute, negatively impacting screen reader focus tracking.
**Action:** Added `aria-live="polite"` to dynamically toggled inline error message elements (`#login-error`, `#signup-error`) and added `for` attributes to all form labels (`<label>`) across the `login.html`, `app.html` (Post Mission Wizard), and `profile.html` (Edit Profile Modal) views. Always verify that dynamic DOM visibility changes include ARIA live regions, and that forms utilize semantic label associations.
