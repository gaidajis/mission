## 2024-10-27 - Accessible Inline Form Validation
**Learning:** In vanilla JS applications that rely on custom validation logic by toggling `display: none` on inline error message elements (e.g., `<p id="error" style="display: none;">`), screen readers will not announce the error when it becomes visible unless the element has `aria-live="polite"` applied directly to it. Also, custom form inputs must always have a `for` attribute on their `<label>` linking to the input `id` to ensure screen reader focus association.
**Action:** Always add `aria-live="polite"` to dynamically toggled inline error text elements and ensure all labels use `for` attributes instead of just relying on proximity, especially when working with custom vanilla JS validation over native HTML5 validation.
