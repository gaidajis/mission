## 2024-05-24 - Form Accessibility & Screen Reader Support for Custom JS Validation
**Learning:** This app relies entirely on custom JavaScript to handle form submissions and errors, toggling error visibility using `display: none`. This pattern is inaccessible by default because screen readers won't announce the dynamically appearing error text. Additionally, using duplicate field names (like "Email" and "Password") across multiple forms (login vs signup) on the same page requires explicit `for` attributes on labels targeting specific IDs to ensure proper form scope for assistive technologies.
**Action:** Always add `aria-live="polite"` to inline error message elements that are dynamically toggled via custom JS (e.g., in `login.html`), and ensure all `<label>` tags explicitly use the `for` attribute linking to unique input `id`s rather than relying on implicit wrapping or generic text matching.
