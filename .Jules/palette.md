## 2024-03-24 - Form validation accessibility and ARIA roles
**Learning:** In a vanilla JS web app where validation errors are toggled by setting `display: none` / `display: block`, screen readers won't announce the error automatically when it appears unless `aria-live="polite"` is used. Also, implicitly wrapping inputs within `<label>` tags is not always sufficient for robust screen reader support across all devices, requiring explicit `for` attributes linking to the input `id`.
**Action:** Always add `aria-live="polite"` to dynamically revealed inline error messages (especially those using inline CSS manipulation). Make sure every form `<label>` explicitly uses `for="inputId"` matching the respective `<input id="inputId">` rather than relying on structural hierarchy or visual proximity.
